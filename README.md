# 安心手记

焦虑治疗期间自用的记录工具，安卓。做三件事：

1. **今天这顿药吃了没** —— 打开就看见，确认一次点击，通知上也能直接点。
2. **压力起来的时候把当时的情况留住** —— 30 秒能写完。
3. **事后回来补：我做了什么、有没有用** —— 攒成自己的应对手册。

> 它不做任何医疗判断。漏服要不要补、剂量怎么调，都听医生的。

## 数据在哪

**只在你这台手机上。** 这个 App 没有 `INTERNET` 权限——不是"承诺不上传"，是系统层面做不到。没有账号，没有云端，没有统计 SDK。

记录存在应用私有目录的一个 JSON 文件里，并且自动备份到 `下载/安心手记/`（放在共享目录是因为卸载 App 会连带删掉私有目录，那次教训见 `BACKLOG.md`）。换手机或者重装之后用设置里的"从备份恢复"读回来。

## 两条设计原则，比功能重要

**不制造第二种压力。** 没有连续天数，没有服药率百分比，不用红色，不出现"漏服""失败""已断"这类词。没记的那天只是空着。给焦虑的人做工具，一个催促的红点就能让他把 App 卸了。

**可以统计方法，不统计人。** 应对方式的平均降幅要算出来给用户看，这是记录换来的回报。依从率和连续天数一律不做——断掉带来的自责会让人放弃记录，甚至开始记假的。

`SPEC.md` 里每一条约束都写了为什么。改之前先读它，尤其是标着"踩过"的那些。

## 技术路子

原生壳 + WebView 里一个单文件页面（`app/src/main/assets/index.html`，无构建步骤、无依赖）。原生侧只管四件 WebView 干不了的事：闹钟和通知、数据落盘、备份到共享目录、系统权限。

之所以数据由原生侧持有：在通知上点"吃了"的时候 App 通常没打开，WebView 里没有 JS 在跑，只有原生能把这一笔落下去。

```
app/src/main/
  assets/index.html           全部界面和交互
  java/com/calmnote/app/
    MainActivity.java         WebView 宿主 + JS 桥
    Store.java                data.json 读写与版本迁移
    Reminders.java            闹钟排程与通知
    Backups.java              备份到「下载」
    ReminderReceiver.java     闹钟、开机、对时
    DoseActionReceiver.java   通知上的「吃了」
```

## 构建

需要 JDK 17 和 Android SDK（compileSdk 34）。

```bash
echo "sdk.dir=/你的/Android/sdk" > local.properties
./gradlew assembleDebug
# app/build/outputs/apk/debug/app-debug.apk
```

界面部分不用编译也能改：直接在浏览器里打开 `app/src/main/assets/index.html`，没有 `Native` 桥的时候它会退回 `localStorage`，除了闹钟以外都能跑。

## 升级时千万不要先卸载

覆盖安装是安全的。**卸载会删掉你所有的记录**，而且救不回来（真的发生过一次）。要换设备就先在设置里备份。

## 提醒不响的话

国产 ROM 上"到点不响"基本都不是通知的问题，是闹钟压根没走到 App 这儿。设置 → 提醒里有自检，包括一条"测一下"：排两分钟后的一条闹钟，点完可以把 App 划掉、锁屏，等它。

- 它响了 → 闹钟链路是通的。
- 它没响 → 被系统拦了，去开自启动和电池白名单，再测。

自启动那条自检永远是灰点：系统没有任何接口能查它开没开，只能给个入口。装作知道状态比不知道更糟。
